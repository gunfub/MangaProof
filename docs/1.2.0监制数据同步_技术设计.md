## 0. 结论摘要

1. **一个平台一个独立模块**：`mangaproof/poprako/`（域） + `mangaproof/ui/poprako_dialog.py`
   + `mangaproof/ui/poprako_worker.py`（界面）。模块划分与现有自更新功能同构
   （`mangaproof/update/` + `ui/update_dialog.py` + `ui/update_worker.py`）。
2. **不抽版式公共模块**：Poprako 对话框自带自己的行/页骨架代码，即使与设置页看起来一样。
   后续平台可以完全长成别的样子，不受共享代码牵制。
3. **零新增依赖**：`httpx`（已在主依赖，含 socks extra）与 `keyring`（已在主依赖）足够。
4. **纯函数承担全部转换逻辑**：匹配与转换不导入 Qt、不发网络，可用
   `httpx.MockTransport` 与普通 `pytest` 离线覆盖。
5. **破坏性动作只有一个**（整体替换导入），它被三重安全阀 + 二次确认 + 回读校验夹住。
6. **单向上传**：只写不读回业务状态。读取远端问题仅用于「统计清空规模」与「保留未映射页」，
   不回拉、不合并、不落本地（见 §9.2）。
7. 预计新增约 3 800 行（含注释与测试），不改动现有业务逻辑。

### 1.2 Poprako 侧事实（已核实）

来源：`poprako-server` 仓库 `docs/swagger.json`（OpenAPI 3.1，91 个 path）、
`docs/issue-upload-api.md`、`docs/chapter-issues.md`；`poprako-web` 仓库
`src/api/client.ts`、`src/api/identity/identity-api.ts`、`README.md`。

- 生产基址 **`https://api.poprako.com/api/v1`**（poprako-web README 明确）。
- 登录 `POST /auth/login`，body `{qid, password}`（**snake_case**），
  响应 `{code: 0, data: {token, user_id}}`。
- 其余接口一律 `Authorization: Bearer <token>`；web 端所有请求 `credentials: "omit"`，
  即**不依赖 Cookie**。
- 响应统一信封 `{code, data}`；失败信封 `{code}`（`HttpError` **没有 message 字段**），
  因此错误文案只能由客户端按 HTTP 状态与业务 code 自行组织，并记日志。
- 分页：`offset` + `limit`（必填，`ListLimit200` 暗示上限 200；本客户端固定取 100）。
- 导入 body 上限存在但未公开（文档原话 "The existing HTTP body limit applies"）。

### 2.2 依赖方向

```text
ui/poprako_dialog.py ──► ui/poprako_worker.py ──► poprako/client.py ──► httpx
        │                        │                      │
        │                        └──► poprako/convert.py（纯函数）
        └──► poprako/credentials.py、poprako/models.py
```

- `mangaproof/poprako/**` **不得** `import PySide6`（保持可离线单测、可被安装器类工具复用）；
- `ui/poprako_*.py` **不得** 被域层导入；
- 主窗口只 import 对话框，不 import 客户端：`from mangaproof.ui.poprako_dialog import ...`。

### 2.3 为什么不抽公共层（决策记录）

| 备选 | 否决理由 |
|---|---|
| 抽象 `UploadProvider` 协议 + 子类 | 各平台鉴权、层级、坐标语义完全不同，协议会立刻长成"最小公倍数 + 一堆 if" |
| 平台注册表 / 动态发现 | 只有一个平台时纯属过度设计；第二个平台接入时又要改注册表，等于没解耦 |
| 共用「映射 + 转换 + 上传」对话框 | 需求方明确要求：一个平台可以有自己的页面结构、预览格式与交互 |
| 抽 `ui/form_page.py` 共享版式原语 | 后续可能按平台调整 UI；共用会把"改一个平台"变成"改全部平台"。**本设计选择各平台自带一份** |

**允许共用的只有**：主窗口菜单接线、`update/redact.py`、`ui/widgets.py` 的两个通用控件、
`ui/theme.py` 的色值常量。

## 3. Poprako API 契约速查

| # | 用途 | 方法与路径 | **data 形态** | 关键字段 |
|---|---|---|---|---|
| 1 | 登录 | `POST /auth/login`（无鉴权） | `object` | req `{qid,password}` → `{token,user_id}` |
| 2 | 校验令牌 | `GET /users/me` | `object` | `id, qid, nickname, is_sadmin` |
| 3 | 我的团队 | `GET /members/me?incl=team&offset=0&limit=100` | `array` | `team_id, roles(bitmask), team.name` |
| 4 | 项目集 | `GET /teams/{team_id}/worksets` | `array` | `id, name, comic_count` |
| 5 | 作品 | `GET /worksets/{id}/comics?status=active` | **`object.comics`** | `id, title, author, is_archived, chapter_count` |
| 6 | 章节 | `GET /comics/{id}/chapters` | `array` | `id, index, subtitle, page_count, stages(bitmask)` |
| 7 | 章节详情 | `GET /chapters/{id}` | `object` | 同上 |
| 8 | 复合图页 | `GET /chapters/{id}/page-artworks` | `array` | `id, index, raw_ident, image_uploaded, ext` |
| 9 | 现有问题 | `GET /chapters/{id}/issues` | `array` | `id, page_artwork_id, index, variant, layer_name, rect, note` |
| 10 | **导入问题** | `POST /chapters/{id}/issues/import` | `object` | req `{pages:[…]}` → `{imported_page_count, imported_issue_count}` |
| 11 | 登出（可选） | `POST /auth/logout` | 204 | 仅清 Cookie |

**为什么「data 形态」要单独占一列**（2026-10-20 事故）：`/worksets/{id}/comics` 返回的是
`{comics, pinned_chapters, pinned_chapter_assignments}` 这个**对象**，而我们早期的
`_paged()` 只认裸数组，于是"作品"永远解析成空列表、连带着"章节"根本不会发请求
（`comic_id` 为空）。当时的单测用手写的数组响应喂解析器，测试与实现一起错，所以全绿。

现在的约束：

1. `_paged(path, params, key=None)`：`key` 表示"列表在 `data.<key>` 里"；
2. 形态不符（不是数组、也没有 `data.<key>`）→ **抛 `PoprakoError` 并在状态行显示**
   ——空列表与"解析失败"必须能区分（用户决策 2026-10-20）；
3. `tests/test_poprako_client.py::test_list_endpoints_match_documented_shapes`
   是一张**契约表**：6 个列表端点逐一按上表形态断言解析成功，形态再变会先炸测试。

### 3.1 导入请求结构

```jsonc
{
  "pages": [
    {
      "page_artwork_id": "existing-id",        // 必须属于该章、不可重复
      "issues": [                              // 数组顺序 = 服务端 index（从 0）
        {
          "variant": "文字位置错误",            // 必填，非空白
          "layer_name": "对白图层",             // 可选；省略/null = 整张复合图；不可空白
          "rect": { "x_coord": 0.1, "y_coord": 0.2,
                    "width": 0.3, "height": 0.1 }, // 可选；[0,1]、宽高 > 0
          "note": "向左移动"                    // 必填，可为空，保留换行
        }
      ]
    }
  ]
}
```

- `additionalProperties: false` → 只能出现上面四个键；
- `pages: []` 或全部 `issues: []` 会清空该章问题，但**不会**删除复合图页/图片、不推进流程；
- 未出现在 `pages` 中的复合图页，其旧问题**会被清除**。

### 3.2 权限与拒绝条件

| 情况 | 结果 |
|---|---|
| 当前用户不是该章节的 `REVIEWER` 指派 | `403`（仅 ADMIN 不够） |
| 章节已发布 | `422` |
| 章节不存在 / 字段不合法 / 目标页不属于该章 | `422` |

`REVIEWER` 位 = `RoleMask` 的 `32`。章节发布态取 `stages` 的 publish 字段
（bits 10–11，`completed` 视为已发布）。

### 3.3 我们不使用的接口

`/teams`（需要 `user_id` 查询参数，超管才能全省）、`/auth/register`、
`/page-artworks/*/alloc`、`/stage/advance`、各类 avatar/cover/termbase 接口。

全部为 `@dataclass(frozen=True)` + `from_api()` 类方法，解析时**逐字段容错**

|---|---|

| `User` | `id`, `qid`, `nickname`, `is_sadmin` |
| `Membership` | `team_id`, `team_name`, `roles: int`；`is_reviewer` 属性 = `roles & 32` |
| `Workset` | `id`, `name`, `comic_count` |

## 5. 鉴权实现

### 5.1 凭据存储（`poprako/credentials.py`）

与 `update/cdk_store.py` 同构，独立一套常量：

```python
KEYRING_SERVICE = "MangaProof"
KEYRING_USERNAME = "poprako_token"
```

| 函数 | 行为 |
|---|---|
| `keyring_available()` | `set → get → delete` 实测（探测键用完即删） |
| `load_token(poprako_settings)` | keyring 读不到再读 settings 明文字段 |
| `save_token(settings, token)` | keyring 可用 → 写 keyring 并清空明文字段；否则写明文 |
| `clear_token(settings)` | 两处都删（空值即清除，避免旧值回魂） |
| `migrate_plaintext(settings)` | 发现明文且 keyring 可用 → 迁入 keyring 并删明文（回滚安全：失败保留明文） |

`token` 在 settings 里只是**运行时存储位**，界面上不显示、不编辑。

### 5.2 登录 / 校验 / 登出时序

```text
打开对话框
  ├─ settings.poprako.token 为空 ──► 显示未登录，"目标章节"整页置灰
  └─ 非空 ──► GET /users/me
                ├─ 200 ──► 已登录态（显示昵称/qid）
                └─ 401 ──► 清令牌 ──► 未登录态 + 状态行橙色提示

点「登录」──► POST /auth/login
                ├─ 200 ──► save_token(data.token) + 存 user_id/qid/nickname
                │          └─ 自动跳到「目标章节」并拉取团队
                ├─ 401 ──► "QQ 号或密码不正确"
                └─ 其它 ──► 按错误映射表提示，输入框不清空

点「退出登录」──► clear_token() + 清显示态（best-effort POST /auth/logout）
```

密码控件为 `QLineEdit.Password`，登录请求返回后立即丢弃引用；**没有任何代码路径把
密码写入 settings、任务文件或日志**。

## 6. HTTP 客户端（`poprako/client.py`）

```python
class PoprakoClient:
    def __init__(self, base_url=API_BASE, token="", *, proxy="", timeout=(5.0, 20.0),
                 max_retries=2, retry_delay=0.6, transport=None, user_agent=None)
    # 鉴权
    def login(self, qid: str, password: str) -> AuthSession
    def me(self) -> User
    def logout(self) -> None
    # 层级
    def my_teams(self) -> list[Membership]
    def worksets(self, team_id) -> list[Workset]
    def comics(self, workset_id) -> list[Comic]
    def chapters(self, comic_id) -> list[Chapter]
    def chapter(self, chapter_id) -> Chapter
    # 页面与问题
    def page_artworks(self, chapter_id) -> list[PageArtwork]
    def issues(self, chapter_id) -> list[RemoteIssue]
    def import_issues(self, chapter_id, payload: dict) -> ImportResult
```

实现要点：

1. **信封解包**（`_request()` 单点）：
   - `204` → `None`；
   - JSON 且 `code == 0` → 返回 `data`；
   - `code != 0` 或 HTTP ≥ 400 → 抛对应异常，异常消息只含 `HTTP 状态 + 业务 code`，
     原始 body 走 `log.warning` 并按 `redact` 处理。
2. **异常族**（`errors.py`）：
   `PoprakoError` → `PoprakoAuthError(401)` / `PoprakoForbiddenError(403)` /
   `PoprakoValidationError(422, code)` / `PoprakoHTTPError(status)` /
   `PoprakoNetworkError`。UI 只按类型分支，不解析字符串。
3. **分页**：`_paged(path, key)` 固定 `limit=100`，`offset += 100` 直到返回不足一页，
   最多 20 页（防服务端异常导致死循环）。
4. **重试**：仅 `httpx.TransportError` / 读超时重试 **2 次**（线性退避 0.6 s / 1.2 s）；
   4xx/5xx 不重试。`import_issues` 重试**安全**（整体替换语义幂等）。
5. **超时**：连接 5 s、读 20 s（2026-10-20 调参：原来 10 / 30 s，代理挂掉时要干等
   10 s 才报错；实测直连失败单次就要 12 s+）。上传沿用（payload 是 JSON，通常远小于 2 MB）。
6. **请求头**：`Accept: application/json`、`Content-Type: application/json`
   （带 body 时）、`Authorization: Bearer <token>`、
   `User-Agent: MangaProof/<__version__>`。
7. **代理**（2026-10-20 追加，需求 §5.1）：`PoprakoClient(proxy=...)`；
   **一律 `trust_env=False`** —— `proxy` 为空即直连，非空则只走该代理（与自更新功能同一口径）。
   好处之一：`NO_PROXY` 里裸 IPv6 会让 httpx 在 `trust_env=True` 时构造崩溃，这条路径彻底
   绕开它。校验/探测/遮罩/工厂四件套同文件导出：

   ```python
   def validate_proxy(text) -> tuple[str, str]        # (规范化值, 错误说明)；空值合法
   def probe_connection(proxy, *, timeout=10.0) -> tuple[bool, str, int]  # poprako.com + 毫秒
   def mask_proxy(text) -> str                        # http://***@host:port，只用于日志
   def create_client(base_url, proxy="") -> PoprakoClient   # UI 工厂契约 (base_url, proxy)
   ```

   `probe_connection` 打 **`https://poprako.com/`**（`SITE_URL`）：**任何 HTTP 响应都算连通**
   （401/403/404 也算），只有 `httpx.HTTPError` 才算失败；返回里带**往返毫秒**
   （≥ `SLOW_PROBE_MS` 的文案标"较慢"，界面转橙）。留空时测直连——用来回答
   "不设代理到底通不通"。探针与业务请求共用 `_build_http_client`，UA / `trust_env` /
   超时口径完全一致（"测的就是用的"）。

   **工厂契约（2026-10-20 修）**：UI 只认 `(base_url, proxy)` 两个位置参数，
   默认工厂是 `create_client`，**不能**直接传 `PoprakoClient` ——
   它的第二个位置参数是 `token`，`proxy` 是关键字参数；直接传类会让代理串落进
   `token`、代理静默失效（见 `docs/开发踩坑记录.md` 第 6 条）。
8. **传输层失败的文案要分清链路**：`PoprakoNetworkError(via_proxy=…)` 由客户端按
   **实际生效的代理**填写；`user_message()` 据此给出不同下一步——直连失败提示
   "可在「代理」页设置代理后重试"，代理失败则提示检查代理本身。
9. **日志**：`log.info("%s %s → %s (%d ms)", method, path, status, elapsed)`；
   payload/body 只以 `redact_mapping` / `redact_url` 后的形式出现。

## 7. 匹配算法（`poprako/mapping.py`）

```python
def auto_match(files: Sequence[str], pages: Sequence[PageArtwork]) -> MatchResult
def align_in_order(files, pages, current: dict[str, str]) -> dict[str, str]
def normalize_ident(text: str) -> str
```

`MatchResult` = `mapping: dict[str, str]`（本地相对路径 → page id）、
`unmatched_local: list[str]`、`unmatched_remote: list[PageArtwork]`、
`ambiguous: list[tuple[str, list[str]]]`。

### 7.1 规则（按顺位，命中即锁定）

| 顺位 | 比较对象 | 说明 |
|---|---|---|
| 1 | `normalize(file_rel) == normalize(raw_ident)` | 统一 `/`、去 `./`、小写 |
| 2 | basename 相等 | `ch1/001.psd` ↔ `001.psd` |
| 3 | stem 相等 | `001.psd` ↔ `001` |
| 4 | 数字段相等 | 取最后一段连续数字：`001.psd` ↔ `001`、`page_01` ↔ `01` |

### 7.2 歧义与冲突

- 同一候选被多个本地文件命中 → 全部记为 `ambiguous`，**不自动选**；
- 一个远端页只能被一个本地文件占用（后写覆盖并回报前一行）；
- `align_in_order` 仅在数量相等或前缀可确定时按自然序对齐，其余保持未映射。

### 7.3 复杂度

`O(F × P)`，F 为本地文件数、P 为远端页数（典型 ≤ 200），逐级用字典索引降为近似线性；
百页章节匹配耗时在毫秒级，不需要后台线程。

### 7.4 作品名匹配与排序（`poprako/title_match.py`，1.2.0 追加）

**目的**：作品多时，把与"当前任务的作品名"最像的排到前面，并在下拉里把命中的字标绿。

**任务名**：`utils/task_naming.py::task_display_name`（与返修单默认名同一实现）。

**归一化**：`NFKC` → 小写 → 去分隔符；另生成"去括号噪声""去章节号""两者都去"共 4 组变体：

```python
_FLAGS = ((False, False), (True, False), (False, True), (True, True))
```

**打分**（对每一对变体取最高）：

```python
ratio = SequenceMatcher(None, a, b).ratio()
dice  = 2*|A∩B| / (|A|+|B|)        # 字符二元组，对中文插入语更稳
score = 0.65*ratio + 0.35*dice
if a in b or b in a:  score = min(1.0, score + 0.15)
```

**排序**：分数降序 → 标题自然序 → 原名次序；**全部重排、不设阈值**（2026-10-20 决策）。
实测 1000 部作品约 66 ms——真正的耗时在分页请求，所以进度窗主要汇报"读到第几页"。

**高亮区间**：取最高分那一对变体的**最长公共子串**（≥ 2 字），用归一化时保留的
"归一化字符 → 原文下标"映射回原始位置；UI 用富文本渲染该区间为 `#4caf50`。

**为什么保留映射**：归一化会删括号、删章节号、删标点，删完之后必须能回到原文下标，
否则绿字会标偏。

## 8. 转换算法（`poprako/convert.py`）

```python
@dataclass
class PreflightReport:
    pages_written: int
    issues_written: int
    pages_cleared: list[tuple[str, int]]   # 将被清空且当前有问题的远端页：(显示名, 旧问题数)
    pages_preserved: int
    issues_preserved: int
    unmapped_with_issues: list[tuple[str, int]]   # 本地未映射且含问题 → 阻塞
    unmapped_without_issues: list[str]            # 本地未映射但没问题 → 只提示
    missing_sizes: list[str]
    clamped_rects: int
    dropped_rects: int
    estimated_bytes: int
    blocking: list[str]                   # 非空 → 禁止上传
    warnings: list[str]
    is_blocked: bool                      # 属性：bool(blocking)

def build_payload(*, files, issues, base_dir, mapping, pages,
                  remote_issues=(), preserve_unmapped=True,
                  sizes=None, max_payload_bytes=2 MiB) -> tuple[dict, PreflightReport]
def read_psd_size(path: Path) -> tuple[int, int] | None   # 26 字节头；坏文件返回 None
def normalize_rect(rect_px, size) -> RectResult            # rect/clamped/dropped/empty
```

调用方（对话框）传 `files=task.files 的相对路径列表`、`issues=task.issues`；
`max_payload_bytes` 只为测试可注入，生产不传。

### 8.1 步骤

1. **校验映射**：`page id` 在远端清单内、不重复；本地相对路径存在于 `task.files`。
2. **取尺寸**：每页 `W,H`；优先传入的缓存，否则 `read_psd_size()`（读不到 → 记 `missing_sizes`）。
3. **生成本地页的问题**：
   - 按 `issue_no` 升序（同号按 `issue_id` 稳定排序）；
   - `variant` = `type.strip() or "问题"`；
   - `layer_name` = `layer_name.strip()` 或省略；
   - `note` = `comment`（原样）；
   - `rect` 见 §8.2。
4. **未映射页处理**：
   - `preserve_unmapped=True`：把远端现有问题**原样重建**进 payload（页按远端 `index` 排序，
     问题按远端 `index` 排序）——重建会换新 ID，但内容不丢；
   - `False`：不写这些页（= 清空），记入 `pages_cleared`。
5. **排序**：`pages` 按远端页 `index` 升序（与远端展示顺序一致）。
6. **体积**：`len(json.dumps(payload, ensure_ascii=False).encode())`，> 2 MB 加警告。

### 8.2 矩形归一化

```python
x = clamp(x_px / W, 0.0, 1.0)
y = clamp(y_px / H, 0.0, 1.0)
w = min(w_px / W, 1.0 - x)
h = min(h_px / H, 1.0 - y)
if w <= 1e-6 or h <= 1e-6:      # 退化：整键省略（服务端要求宽高 > 0）
    return None
return {"x_coord": round(x, 6), "y_coord": round(y, 6),
        "width": round(w, 6), "height": round(h, 6)}
```

被钳制（越界或超出右/下边）计 `clamped_rects`，被丢弃计 `dropped_rects`，都在预览页提示。

四类结局分开计数（`:class:`RectResult``）：**空框**（宽高都为 0，即没画框）静默省略、
不计数；**退化**（只有一维为 0 / 非有限值）计 `dropped_rects`；**越界**钳制后照发，
计 `clamped_rects`；取整后又用 `1 − x` 兜一次底，保证 `x + width ≤ 1`。

### 8.3 示例

输入（`001.psd`，1024 × 1536，一条「文字位置错误」）：

```jsonc
{"file": "001.psd", "layer_name": "我明白了", "type": "文字位置错误",
 "comment": "整体向左移 4px", "issue_no": 7,
 "rect": {"x": 422.4, "y": 278.3, "w": 178.4, "h": 98.4}}
```

输出：

```jsonc
{"pages": [{
  "page_artwork_id": "pa_7f3c",
  "issues": [{
    "variant": "文字位置错误",
    "layer_name": "我明白了",
    "rect": {"x_coord": 0.412500, "y_coord": 0.181185,
             "width": 0.174219, "height": 0.064063},
    "note": "整体向左移 4px"
  }]

```

### 8.4 预检与阻塞项

`blocking` 非空即禁止上传，内容示例：

- `本地 003.psd 有 7 条问题，但还没有对应复合图页`；
- `001.psd 读不到画布尺寸，无法归一化红框`;

## 9. 上传流程

### 9.1 时序

```text
[预览与上传页] 点「上传」
   ↓
二次确认（四要素 + 勾选「我确认整体替换」）
   ↓
主线程：用当前映射重新 build_payload（拿到最终 payload 与 report）
   ↓  report.blocking 非空 → 中止并提示
UploadWorker (QThread)
   ├─ POST /chapters/{id}/issues/import
   ├─ GET  /chapters/{id}/issues   → 校验条数与覆盖页数
   └─ 失败按错误矩阵映射成中文提示
   ↓ 信号回主线程
成功：写 task.integrations.poprako.last_upload_*，emit binding_changed → 主窗口 save_task()
     预览页顶部绿字「已同步：18 页 37 条」，底部状态行加「上次同步 18:40」
失败：状态行红字 + 具体原因；不改任务、不改映射
```

### 9.2 为什么上传后要回读（以及单向上传的边界）

服务端返回的 `imported_page_count / imported_issue_count` 是**服务端计数**，
回读 `GET /issues` 才能在"请求成功但内容不符预期"（例如页面被并发改动）时发现偏差，
并把真实结果记录到任务里。

**单向上传边界（长期约束，2026-10-20 决策）**：本功能只写不读回业务状态。
`GET /issues` 只有两个合法用途 —— 统计"将被清空多少条"、以及开启「保留未映射页」时
把这些页的问题原样写回同一次导入请求。禁止把远端问题写入 `integrations`、参与本地统计、
或在界面上提供"拉取/覆盖本地"的入口；回读校验也只比较计数与覆盖页数，不保存问题内容。

### 9.3 失败矩阵

| 失败 | UI 文案 | 任务/令牌 |
|---|---|---|
| 网络不可达 / 超时 | 直连：无法连接 api.poprako.com（当前为直连，可在「代理」页设置代理后重试）；代理：无法连接 api.poprako.com（请检查网络或代理）；均可安全重试 | 不变 |
| 401 | 登录已失效，请重新登录 | 清令牌 |
| 403 | 需要该章节的「监制」指派，管理员身份不足以同步 | 不变 |
| 404 | 章节或复合图页已不存在，请刷新目标 | 不变 |
| 422 | 提交内容被拒绝（HTTP 422 / code xxxx）；附预检结论 | 不变 |
| 429 | 请求过于频繁，请稍后再试 | 不变 |
| 5xx | 服务器错误（HTTP 5xx），稍后重试；重试是安全的 | 不变 |

任何提示文本都不含令牌与密码（异常消息在构造时就只放状态码与业务 code）。

- 代理含账号密码时：状态行提示"会明文保存在 settings.json"，日志与状态行只显示
  `http://***@host:port`。

- 「按名称匹配度排序作品」胶囊开关默认开，状态存 `settings.poprako.rank_comics`；
- 信息行为只读（右对齐值）；
- 警示行最多一条、wordWrap、`COLOR_WARN`；
- 底部两个按钮：`[清空所有选择]`（团队列表保留）与 `[加载章节信息]`（仅选好章节时可用）。

```text
┌ 正在整理作品列表 ───────────────────────┐
│ 正在读取作品…（第 3 页，已获取 200 条）  │
│ ████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  │
│ 完成后即可选择作品；这一步不会修改任何数据 │
└─────────────────────────────────────────┘
```

- **只要开启排序就一定弹**（2026-10-20 决策），不可取消；
- 阶段：读取（不确定进度，文案带页数与已获取条数）→ 匹配（确定进度 i/N）→ 排序；
- 最短可见 0.45 s，避免一闪而过；完成后自动关闭并恢复交互。

### 10.7 状态与门禁

| 条件 | 目标页 | 映射页 | 上传按钮 |
|---|---|---|---|
| 未登录 | 整页置灰 | 空态 | 禁用（先登录） |
| 未选章节 | — | 空态 | 禁用 |
| 章节已发布 | 橙警示 | 可看 | 禁用（已发布章节拒收） |
| 非 REVIEWER | 橙警示 | 正常 | 禁用（需要监制指派） |
| 无复合图页 | 橙警示 | 空表 | 禁用 |
| 有含问题的未映射本地页 | — | 橙色摘要 | 禁用（列出文件名） |
| 全部就绪 | 正常 | 正常 | 可用 |

所有禁用都是**置灰 + tooltip**，不 show/hide。

### 10.8 与规范的三处刻意偏离

1. 底部为「状态行 + 关闭」，不是「确定 / 取消」——本窗口是同步工作区，登录/选择/映射
   即时生效或关闭时保存；唯一破坏性动作由上传自身二次确认把关；
2. 映射页与预览页不套外层滚动区——表格与预览自带滚动，避免双滚动条；
3. 不加页头右侧徽标——上下文摘要统一放在底部状态行；
4. （2026-10-21）底部条不止「状态 + 关闭」：映射页的两行摘要也住在这里，
   与状态文字同一行；因此下边留白从 24 收到 16，让整条落在侧栏下方空间的正中。

## 11. 存储设计

### 11.1 `settings.json`

```jsonc
"poprako": {
  "base_url": "https://api.poprako.com/api/v1",
  "token": "",
  "user_id": "", "qid": "", "nickname": "",
  "keep_signed_in": true,
  "preserve_unmapped": true,
  "last_team_id": "", "last_workset_id": "", "last_comic_id": ""
}
```

实现：`PoprakoSettings` dataclass（`to_dict/from_dict`，非法值回落默认），
`Settings.poprako` 字段，`SettingsManager._load/_save` 接线。
**不进设置对话框**：服务器地址放在同步窗口「账号」页。

### 11.1b `poprako_last.json`（上次选择，**不进 settings.json**）

与 `recent.json` 同级、同性质的"使用痕迹"文件（2026-10-20 决策）：

```jsonc
{
  "version": 1,
  "team_id": "t_1", "team_name": "木叶翻译组",
  "workset_id": "w_1", "workset_name": "2026 春季",
  "comic_id": "co_1", "comic_title": "某漫画"
}
```

- 只用于在下拉项后追加 `（上次）` 标注，**不自动选中**（逐级懒加载要求用户自己选）；
- 原子写（`.tmp` + `replace`）；读取失败一律当"没有记录"，写失败只记日志——
  "记不住上次"绝不能挡住同步流程。

### 11.2 任务文件

```jsonc
"integrations": {
  "poprako": { "chapter_id": "", "chapter_label": "", "team_id": "", "workset_id": "",
               "comic_id": "", "pages": {"001.psd": "pa_7f3c"},
               "last_upload_at": "", "last_page_count": 0, "last_issue_count": 0 }
}
```

实现：`TaskState.integrations: dict[str, dict]`（默认 `{}`），`to_dict` 直出、`from_dict`
原样读；`schema_version` 保持 1。旧文件无此键 → 空字典；旧版本读新文件 → 忽略未知键。
平台只能读写 `integrations["poprako"]`。

## 12. 主窗口接线

```python
# _build_menus()：文件之后、设置之前
sync_menu = menubar.addMenu("监制数据同步")   # 无 & / 无快捷键
self.action_sync_poprako = QAction("同步到 Poprako…", self)
self.action_sync_poprako.triggered.connect(self._open_poprako_sync)
sync_menu.addAction(self.action_sync_poprako)

# _refresh_enabled_state()：**不**给本入口加 has_task 判断（永远可点）

# 打开（允许没有任务）
def _open_poprako_sync(self):

    dialog = PoprakoSyncDialog(self.task, self._base_dir, self.settings, parent=self)
    dialog.settings_committed.connect(self._save_settings)
    dialog.binding_changed.connect(self.save_task)
    dialog.exec()
```

- **入口永远可点**（2026-10-20）：没打开任务也能进去登录 / 设代理。对话框用
  `task=None, base_dir=None` 构造，内部 `_task_open=False`：
  侧栏「目标章节 / 页面映射 / 预览与上传」三项禁用（文字调暗 + tooltip），
  页面本体 `setEnabled(False)`；账号 / 代理照常可用；关闭时不写任务绑定。
- `binding_changed` → 主窗口 `save_task()`（无任务时它是空操作）；
- 第二个平台接入时：菜单加同级子项 + 一个打开方法——不改动 Poprako 的任何文件。

## 15. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 导入是整体替换，误操作会抹掉远端标注 | 数据丢失 | 三重安全阀 + 四要素确认 + 默认保留未映射页；上传前可导出 JSON 留档 |
| 服务端矩形校验严格（宽高 > 0、四边在 [0,1]） | 整批 422 | 本地钳制 + 退化框省略 + 预检拦截 |
| 服务端 body 上限未公开 | 大章节失败 | 2 MB 预警；失败时提示可拆章操作（不在本版本自动拆分） |
| 远端复合图与本地 PSD 宽高比不同 | 红框位置偏移 | 预览页显示每页 `W×H`；后续可选下载缩略图比对宽高比（本版本不做） |
| 令牌明文回退 | 凭据泄露风险 | 界面明示 + 优先 keyring + "保持登录"可关 |
| `REVIEWER` 权限判定可能与服务端不一致 | 上传被 403 | 客户端只做提示性预检，服务端为准；403 文案明确 |
| 并发：别人同时在网页上改问题 | 覆盖对方改动 | 上传前读取现存问题数并展示；保留未映射页；未来可做冲突提示 |
| 新增菜单项挤占 Android 窄屏菜单栏 | 菜单显示异常 | 四项均为短文本；P3 在 Android 构建后目视检查，必要时缩短为「同步」 |
