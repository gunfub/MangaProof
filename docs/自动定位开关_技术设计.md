# MangaProof 自动定位与缩放开关 · 技术设计

> 目标：给「图层自动定位 + 自动缩放」加一个**总开关**（默认开）。关闭后切换图层
> 不移动画布，只靠蓝色虚线框提示当前图层；翻页 / 打开文件回到「整页视角」。
> 涉及代码：`config/settings.py`、`ui/settings_dialog.py`、`ui/main_window.py`、
> `ui/viewer_widget.py`；**`camera/centering.py`、`camera/zoom.py`、`ui/preloader.py` 零改动**。
> 回归：`tests/test_auto_locate.py`（新增）、`tests/test_settings_dialog.py`（胶囊清单 7 → 8）。

---

## 0. 结论摘要

1. 开关架在**调用层**（`MainWindow`），不进 `position_bounds()`：后者同时被蓝色虚线框
   与自动框选使用，一旦在里面短路，这两处会被一起误伤。
2. 相机写入收敛成**一个入口** `ViewerWidget.recenter_on_rect()`：图层定位与整页视角
   共用同一份缩放公式（`fit_zoom`），不再各抄一遍。
3. 关闭期间 `bg / bg 拷贝 的独立比例` **整块置灰且不生效**（含显式「定位当前图层」）——
   设置页是双开关联动，"灰着的下拉"不允许被程序化勾选"复活"。
4. **预热链路一行不动**：蓝色虚线框仍要图层数据，跳过预热只会把"后台解像素"变成
   "UI 线程解像素"。

## 1. 现状：定位链路与两个统一接口

```
       来源 A：视觉内容包围盒（解像素，桌面默认）┐
                                                 ├─► position_bounds(info, mode)   ← ① 矩形来源统一
       来源 B：PSD 图层原始框（零解析，Android）┘            │
                                                             ├─► recenter_on_layer() ─┐
       整页视角：画布 (0,0,W,H) ────────────────────────────────────────────────────┴─► recenter_on_rect()  ← ② 相机数学统一
                                                                                            │
                                                                                            └─► Camera + camera_changed

       ③ 策略统一：什么时候调用 ② —— 只在 MainWindow._select_layer_internal / _fit_page_view
```

所有图层切换入口（列表双击、←→、标完自动跳下一个、统计面板图层芯片、异步预热回调）
最后都收敛到 `_select_layer_internal()`，所以**门控只写一处**，同步/异步两条路径天然一致。

## 2. 行为矩阵

| 触发 | 开（默认，改造前行为） | 关（新） |
|---|---|---|
| 切图层 | 当前图层居中 + 显示比例 | **相机不动**，只刷新蓝框 |
| 翻页 ↑↓ / 打开文件 / 打开任务 | 当前图层居中 + 显示比例 | **整页居中 + 显示比例 100%** |
| 「定位当前图层」 | 当前图层居中 + 显示比例 | 同左，但比例恒取**全局**（bg 独立比例不生效） |
| 设置点确定 / 改显示比例 / 切定位依据 | 立即重新定位 | **不挪画布**（把开关从关改开时会定位一次） |
| 工具栏改显示比例 | 立即重新定位 | 只存值，不挪画布 |

「显示比例 100%」是 contain 语义（宽、高都完整装下、不裁边），**不是**状态栏那个 1:1 像素缩放。
（2026-10 起 `fit_zoom` 由"最长边铺满"改为 contain；常规竖版页面在横版窗口里的数值不变，
左右并排的半栏下才会明显小于旧算法——详见 `docs/左右并排对比_技术设计.md`。）

## 3. 整页模板为什么取画布，而不是 bg

需求方原话是"以 bg（含回退）也就是整页为模板"。实现上取的是**画布** `doc.size`：

| 模板 | 正常 PSD | 异常 PSD | 代价 |
|---|---|---|---|
| 画布 `(0,0,W,H)`（采用） | 与 bg 边界逐像素相同（merged 图就是画布） | 永远正确 | 零 |
| bg 图层边界（不采用） | 同上 | bg 比画布小时更"贴图" | `bg_layer_id()` 的回退分支走 `_has_content() → layer_image()`，**UI 线程 0.3～1s**；且首帧要等阶段 B，会出现"先画布、后跳一下" |

`_fit_page_view()` 因此**一次 `bg_layer_id()` 都不调用**（`tests/test_auto_locate.py` 用
计数桩钉住）。"bg / 回退"继续只负责决定**哪一层是整页基准图**（对比与显示），不参与几何。

### 4.1 门控为什么写在 `_select_layer_internal`

```python
self._refresh_viewer_outline()          # ← 无条件：蓝框不归开关管
if auto_position is None:
    auto_position = self.settings.auto_locate
if auto_position:
    self.viewer.recenter_on_layer(info, self._effective_display_ratio(info), self.settings.position_mode)
```

- **不能提前 return**：否则蓝框跟着一起消失；
- **`auto_position` 三态**：`None` 跟随设置（切图层）、`True/False` 显式指定（打开文件的
  首帧把 `settings.auto_locate` 直接传进来，关着时不定位、改由 `_fit_page_view()` 摆整页，
  只写一次相机，不抖）。

## 5. bg 独立比例：双开关置灰

`bg / bg 拷贝 使用独立的自动显示比例` 自己没有"置灰"以外的状态机，但它下面两个下拉的
`setEnabled` 现在由**两个**开关共同决定：

```python
auto = self.auto_locate_check.isChecked()
self.bg_ratio_check.setEnabled(auto)                       # 总开关也灰
enabled = auto and self.bg_ratio_check.isChecked()         # ← 读状态，不跟事件
self.bg_ratio_combo.setEnabled(enabled)
self.bg_copy_ratio_combo.setEnabled(enabled)
```

真值表（`tests/test_auto_locate.py::test_bg_rows_follow_both_switches` 逐行钉住）：

| auto | bg 勾选 | bg 开关 | bg 下拉 | 拷贝下拉 |
|---|---|---|---|---|
| 开 | 否 | 可用 | 灰 | 灰 |
| 开 | 是 | 可用 | 可用 | 可用 |
| 关 | 是 | 灰 | 灰 | 灰 |
| 关 | 否 | 灰 | 灰 | 灰 |

两条硬约束：

1. **唯一写入点**：这两个下拉的 `setEnabled` 只许出现在 `_update_bg_ratio_enabled()` 里。
   若给 `bg_ratio_check.toggled` 另挂一段 `lambda c: combo.setEnabled(c)`，自动定位关闭时
   勾一下就能把本该灰着的下拉"复活"。
2. **读状态、不跟事件**：槽函数无参、每次按两个控件的 `isChecked()` 重算。`_reset_defaults()`
   与测试都会程序化 `setChecked`，同样会发 `toggled`——只有重算才不会算错。

运行期同样不生效：

```python
enabled = settings.bg_ratio_enabled and settings.auto_locate and doc is not None
```

关闭期间唯一的调用方是显式「定位当前图层」，按需求方口径一律用全局比例；顺带
**一次 `bg_layer_id()` 查询都不做**（它的回退分支要解像素）。

数值本身**保留**：`apply_to()` 照读、`settings.json` 照存，开关打开即恢复生效。

## 6. 不变量与禁区

| 位置 | 规则 | 违反的后果 |
|---|---|---|
| `_layers_need_warm()` | 只看 `position_mode`，**不看** `auto_locate` | `_layer_ready()` 变 True → `_refresh_viewer_outline()` 在 UI 线程解像素 → 切图层卡死 |
| `_refresh_viewer_outline()` | 仍在 recenter 之前**无条件**调用 | 蓝框消失 |
| `_request_layer_switch()` 异步路径 | 保留 | 未预热图层的蓝框会走同步路径，UI 冻结 |
| `camera/centering.py` | 不动 | 蓝框与自动框选共用 `position_bounds()`，改了会一起坏 |
| `camera/zoom.py::resolve_display_ratio` | 保持纯函数 | 把"要不要用独立比例"的判断塞进去，规则就没法单测了 |

> **已撤回的设想**：曾考虑"自动定位关 + 蓝框关 → 图层预热整段跳过"。它能让
> `_layers_need_warm()` 返回 False，但那会让 `_refresh_viewer_outline()`（蓝框关时早退，
> 安全）之外的 `auto_box_current_layer → auto_box_rect → position_bounds` 在 UI 线程
> 解像素。收益只覆盖"两个开关都关"的小众配置，风险不划算，**不做**。

`tests/test_auto_locate.py`（26 条）分五组：

1. 设置：默认 True / 缺键 / 往返 / 关闭时 bg 值不丢；

## 9. 0 图层文件（需求 §88）：本开关对它无效

把图片拖进 Photoshop、未做处理直接保存的 PSD，文件里**一个图层都没有**
（layer count = 0，只有 merged image）。这类文件没有"当前图层"，定位链路
`recenter_on_layer()` 需要 `LayerInfo`，根本走不到——改造前打开它相机不动，
首次打开停在 `(0,0)@100%`，只能看到左上角一块；从普通页翻过来则残留上一页的位置。

处理方式（2026-10 需求方确认）：

| 场景 | 行为 |
|---|---|
| 打开 / 翻页到 0 图层文件 | `_fit_page_view()`：**画布**居中 + 显示比例 100% |
| 「自动定位与缩放」开关 | **不影响**——这类页没有可切换的对象，整页就是唯一视角 |
| 工具栏「定位当前图层」 | `recenter_current_layer()` 在没有当前图层时退化成整页视角，不再"点了没反应" |
| 蓝色虚线框 | 无图层 → 不画（`_refresh_viewer_outline()` 传 `None`） |

两处落点：

```python
# _open_file_internal：0 图层分支，无条件整页视角
if not layer_ids:
    self._current_index = -1
    self.viewer.set_issues(...)              # 面板刷新照旧
    self._refresh_viewer_outline()
    self._fit_page_view()                    # ← 不再判断 auto_locate

# recenter_current_layer：没有当前图层 → 用画布兜底
doc = self.current_doc
if doc is None:
    return
if not (0 <= self._current_index < len(doc.layers)):
    self._fit_page_view()
    return
```

`_reposition_after_layout()`（布局就绪后的补定位）因此**不用改**：开关开着时它走
`recenter_current_layer()`，而后者已经会兜底到整页视角。

⚠ 注意区分：**解析失败**的文件不在 `_layer_ids_by_file` 里，`_ensure_doc()` 返回 `None`
后提前返回，不会被当成 0 图层去做整页视角。
