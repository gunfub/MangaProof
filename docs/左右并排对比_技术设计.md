> 状态：已实现，随 1.2.5.alpha 发布。
> 需求依据：需求方 2026-10-28 三轮交互问答（下称"Q&A"）；原型见

> `mangaproof/ui/main_window.py`、`mangaproof/camera/zoom.py`、
> `mangaproof/config/settings.py`、`mangaproof/ui/settings_dialog.py`。

## 1. 背景与结论

现有的对比形态是**闪切**：`Original`（PSD 自带 merged，即成品图）与背景图层
（未嵌字的原图）共用一份 Camera，定时/手动来回切换显示源。它适合"一眼看出差别"，
但画面在跳，不能边看边标。

第二种形态是**左右并排**：把画布固定切成两栏，**左栏原图、右栏成品图**，
两栏共享中心与缩放。它不是"闪切的子模式"，而是一个**独立的显示模式**：

| 决定 | 结论 | 依据 |
| --- | --- | --- |
| 是大前提 | 左栏 = 原图（`bg`）、右栏 = 成品图（merged） | Q&A 第一轮 |
| 模式选择 | 设置 → 对比呈现 →「对比形式：闪切 / 左右并排」 | A1/F4/F5 |
| 开关语义 | **模式，不是开关**：没有进入/退出/复位；Space 在并排下静默无效 | A3/A7/F6 |
| 持久化 | `compare_form` 写入 settings.json，跨文件/跨图层/跨重启保持 | A4/A5/F2 |
| 几何 | 固定 **50/50**，中间 **4px** 分隔条，不做可拖分隔条 | C1/Q4/C2 |
| 相机 | 两栏**永远**共享中心与缩放，不做独立缩放 | B4/D1 |
| 拟合 | 全局改为 **contain**（宽高各试一次取较小），单栏/并排一致 | B1/Q2 |
| 进入视角 | 按对应模式的自动定位处理（`auto_locate` 开→当前图层，关→整页） | B2/Q8 |
| 角标 | 左上角「原图 / 成品图」胶囊；切到并排 3 秒、无任务常显 | C3/Q3/Q5/Q10 |
| 空画布 | 两块空画布 + 分隔线 + 常显角标 + 每栏一份提示 | Q5 |
| 标注 | 并排下**允许**全部标注操作（仅闪切需要"先停再标"） | A9/D2/D4/D5 |
| 无 bg | 左栏回退 merged（与 0 图层文件一致），不拒绝、不退出模式 | E1/E4/E5/Q6 |
| 工具栏 | 并排下「自动对比」仅置灰，**文案不改** | Q1 |
| 底部提示 | 并排下去掉「Space 对比」一段 | Q7 |
| 色彩 | 分隔条 `COLOR_BORDER`；角标深色半透明胶囊 | C6/C3 |

## 2. 术语（先看这一节，代码里两个"Original"不是一个东西）

| 界面 / 文档 | 代码 | 含义 |
| --- | --- | --- |
| **原图** | `SOURCE_BG` / `"bg"` | 背景图层（未嵌字），右图栏的对照基准 |
| **成品图** | `SOURCE_MERGED` / `"merged"` | PSD 自带 merged，即需求文档里的 **Original** |
| 需求文档 "Original" | `SOURCE_MERGED` | **= 成品图**，不是界面上的「原图」 |
| 闪切状态 `ORIGINAL` | `CompareController` | 显示 merged（成品图）；与界面「原图」相反，勿混 |

## 3. 交互规格

### 3.1 事件对照

| 事件 | 闪切（行为不变） | 左右并排 |
| --- | --- | --- |
| `Space`（`toggle_compare`） | 自动开始/停止，或手动翻一次 | **静默无操作** |
| 工具栏「自动对比」 | 自动对比 / 停止 / 对比切换 | 置灰、文案不改 |
| 启动 / 打开任务 | 单栏 merged | 双栏；按 `auto_locate` 定位 |
| 切文件 | 单栏，停闪切 | 双栏保持；左栏按新文件重新判定 bg |
| 切图层（`auto_locate` 开） | 停闪切 → merged → 定位 | 蓝框两栏；当前图层适配半栏 |
| 切图层（`auto_locate` 关） | 只刷新蓝框，相机不动 | 同上，相机不动 |
| 翻页/打开（`auto_locate` 关） | 整页视角 | 整页视角（装进半栏） |
| 拖框 / `Enter` / `/` / 自动框选 | 先停闪切 | 直接允许；红框/蓝框两栏都画 |
| `Esc` | 取消标注；无标注时停闪切 | 只取消标注（并排没有"退出"） |
| 无 bg 图层 | §24 回退层；再失败则提示无法对比 | 左栏回退 merged（静默，不弹提示） |
| 0 图层文件 | 单栏 merged，整页 | 两栏都 merged，整页视角 |
| 关闭任务 | 单栏 | 模式保持；空画布两栏 |
| 重启 | 按配置（默认闪切） | 按配置保持 |

### 3.2 角标 / 状态提示的时机

角标状态机（`ViewerWidget.labels_visible`）：

```text
没有任务                         → 常显（Q5）
有任务 + 刚切到并排（设置页确定）   → 显示 3 秒
有任务 + 启动即并排 + 首个任务     → 显示 3 秒（无任务→有任务）
同任务内换文件 / 换图层            → 不重新显示
切回闪切                         → 立即隐藏；再切回并排重新计 3 秒
```

实现：`set_split_mode(True)` 时若有文档就 `show_labels(3000)`；
`set_document()` 检测"上一个文档为空、新文档非空"时也 `show_labels(3000)`；
没有文档时 `labels_visible` 恒为真，不依赖计时器。

状态栏提示只在**设置页把形式切到并排并成功保存**时出现一次：
`statusBar().showMessage("左原图 / 右成品图", 3000)`。启动时靠角标，不重复打扰。

## 4. 几何

`SplitLayout`（`mangaproof/ui/split_view.py`，纯几何、无 QWidget）：

```text
width = 1200, gap = 4
left  = [0, 598)        598×800
gap   = [598, 602)      4×800   ← COLOR_BORDER
right = [602, 1200)     598×800
fit   = (598, 800)      适配尺寸取左栏（奇数宽度时左栏是较小侧，两栏都装得下）
```

- 宽度为奇数时右栏多 1px（如 1201 → 598 / 599），总数仍严格等于窗口宽；
- 命中判定用**半开区间** `[left, right)`：`QRectF.contains()` 会把右边缘算进去，
  导致 4px 分隔条的第一列被误判成左栏；`Pane.contains()` 显式改成半开；
- 角标位置固定 `pane.x()+10, pane.y()+10`，尺寸由 `QFontMetrics` 算，不随图像移动；
- 空画布同样用这套 `panes()` 画两块棋盘格，分隔条与角标照画。

## 5. 拟合：全局 contain

`mangaproof/camera/zoom.py::fit_zoom` 从"最长边铺满"改为 **contain**：

```text
zoom = ratio × min(viewport_w / target_w, viewport_h / target_h)
```

- 100% = 宽、高都能**完整装下**，不再有"长边铺满、另一边被裁"；
- 比例（默认 60%）乘在 contain 结果上；整页视角固定 `ratio=1.0`；
- 单栏和并排共用同一个函数，区别只在**视口尺寸**：单栏 = 整窗，并排 = 一栏；
- `ViewerWidget._fit_viewport_size()` 是唯一取视口的地方，`recenter_on_rect()`
  因此不需要知道当前是不是分屏。

实测差异（1600×2400 页面）：

| 半栏 | 旧（长边） | 新（contain） | 说明 |
| --- | --- | --- | --- |
| 598×800 | 0.3333 | 0.3333 | 该宽高比下两者一致 |
| 448×800 | 0.3333 | 0.2800 | 旧算法左右各裁约 16% |
| 348×800 | 0.3333 | 0.2175 | 旧算法左右各裁约 35% |
| 398×480 | 0.2000 | 0.2000 | 高度受限，两者一致 |

对单栏的影响：只有在"视口比目标更极端"时才会比旧算法缩小（例如接近正方形的图层
放进很宽的窗口，旧算法按宽铺满、高度超出），现在会保证两边都装下；正常的竖版页面
在横版窗口里结果与旧算法相同。需求方明确要求单栏也统一（Q2）。

## 6. 绘制

`ViewerWidget.paintEvent()`：

```text
无文档:
  单栏 → 棋盘格 + 提示
  分屏 → 每栏: clip + translate → 棋盘格 + 分屏版提示
         分隔条 → 角标（常显）
有文档:
  for pane in _panes():          # 单栏 1 个，并排 2 个
      save → setClipRect(pane) → translate(pane.topLeft())
      棋盘格（每栏各画一次，C8）
      图像（merged 或 bg，bg 带世界坐标偏移）
      Overlay：蓝框 / 问题红框 / 拖框橡皮筋（两栏都画）
      restore
  分隔条 → 角标（按计时）
```

要点：

- **裁剪**保证越界的图像、跨中线的橡皮筋不会串到另一栏；
- 每栏棋盘格从自己的 `(0,0)` 开始，两栏图案相位一致，视觉上对称；
- 图像绘制沿用原来的最近邻/双线性策略与设备像素取整；
- 无 bg 时左栏的 `_left_source()` 返回 merged，两栏内容相同（0 图层文件即此形态）；
- 分屏提示文本由主窗口生成：**每个快捷键一行**（4 行）。半栏较窄，原来
  "`Ctrl+O …　　Ctrl+Shift+O …`" 一整行会被 Qt 在"打开漫画文件夹"中间折断，
  原型里实测 348–398px 都会出现；主窗口通过 `set_empty_hint(text, split_text)` 下发两份。

## 7. 鼠标 / 滚轮

- **命中**：`_pane_at(pos)` 先按半开区间找栏；落在 4px 分隔条上返回 `None`
  （不开始拖拽；滚轮缩放也不响应，平移不受影响）；
- **世界坐标**：一律 `pane.local_pos(pos)` → `Camera.screen_to_world(local, pane_w, pane_h)`；
- **滚轮缩放**：`Ctrl+滚轮` / `wheel_mode="zoom"` 用**光标所在栏**的局部坐标做锚点。
  两栏同宽、共享 Camera，所以同一个局部坐标在两栏指向同一世界点；缩放后该点仍钉在
  光标下（原型实测误差 0.000）；
- **拖框**：可以从任一栏起手；越过中线时只把 x 截在起手栏边缘（Q9），y 允许越界由裁剪裁掉；
  世界坐标连续，不会因为换栏而跳变；红框/橡皮筋两栏都画（D4/D5）；
- **平移**：`pan_by_screen(dx, dy)` 与栏无关，两栏天然同步；左键/中键/触控板双指都保留；
- **原生手势**：macOS 捏合缩放同样按光标所在栏换算。

## 8. 主窗口接线

### 8.1 启动与模式切换

- `_build_ui()`：`viewer.set_split_mode(settings.compare_form == "split")`；
- `toggle_compare()`：`compare_form == "split"` 时**最先返回**（静默，A3/F6）；
- `_update_compare_action_text()`：保持原逻辑；并排下按钮由 `_refresh_enabled_state()` 置灰，
  **不改文案**（Q1）；
- `_update_shortcut_hints()`：并排下不生成「Space 对比」段（Q7），
  同时下发单栏/分屏两份空画布提示。

### 8.2 设置保存

`open_settings_dialog()` 在 `apply_to()` 前记录 `old_form`：

```text
form_changed = old_form != settings.compare_form
if form_changed:
    _apply_compare_settings()      # 停闪切、改 Viewer、刷新按钮/提示
    _reposition_after_layout()     # Q8：auto_locate 开→当前图层；关→整页
    if 新形式 == 并排: statusBar 提示「左原图 / 右成品图」3 秒
```

`_reposition_after_layout()` 是既有函数（布局完成后重算相机），这里复用它，
因为"切模式"本质就是"视口从整窗变半栏（或反向）"。后面的通用分支
`if auto_locate and not form_changed: recenter_current_layer()` 避免重复跳一次。

### 8.3 阶段 B 的 bg 注入

打开文件时 `KIND_OPEN` 只预热 merged + 目标图层，**不含背景图**。分屏下左栏若在
`paintEvent` 里直接调 `doc.bg_image()`，大图会在 UI 线程解像素（0.3～1s）。

实现：

1. `ViewerWidget._left_source()` 只认"已提取过 / 已注入过"的 bg，否则先回退 merged；
2. `MainWindow._on_preload_done()` 在 `KIND_EXTRA` 且 `rel == 当前文件` 时，
   把 `images["bg"]` 注入 Viewer（`inject_qimage` 内部会 `update()`），左栏从 merged 切到原图；
3. 如果文件本身没有 bg（0 图层 / 提取失败），`has_bg()` 为真但 `bg_image()` 为 None，
   左栏持续显示 merged，不会卡、不会反复提取。

## 9. 设置

- 键名：`compare_form`，取值 `"flash"` / `"split"`，默认 `"flash"`；
- 旧版配置缺键 → 默认闪切（升级零行为变化）；非法值 → 回退默认；
- 设置页「对比呈现」：

```text
对比形式：  [ 闪切（Original ↔ 背景，定时/手动） ▼ ]
             [ 左右并排（左原图 / 右成品图）   ]
对比模式：  [ 自动切换 / 手动切换 ]        ← 并排时整行置灰
切换速度：  [ 慢 / 较慢 / 正常 / 较快 / 快 ] ← 并排或手动挡时置灰
```

- 并排时「对比模式 / 切换速度」整行置灰（含标签，`SettingsRow` 的禁用联动），值保留；
- 切回闪切后按原 `compare_mode` 恢复（手动挡仍只灰速度）；
- 对比形式本身**不置灰**，它是切换模式的唯一入口；
- 「对比呈现」页头说明改为"对比形式（闪切 / 左右并排）与闪切方式、速度"。

## 10. 性能

原型（`.scratch/split_spike.py`，3000×4500 假图、1200×800 窗口、`grab()` 连跑 20 次取中位数）：

| 场景 | 双栏 | 单栏 | 增量 |
| --- | --- | --- | --- |
| fit（zoom<1，1x DPR） | 6.89 ms | 6.17 ms | +0.72 |
| 100%（1x） | 5.02 ms | 4.99 ms | +0.03 |
| 空画布（1x） | 4.98 ms | 4.70 ms | +0.28 |
| fit（2x DPR） | 11.04 ms | 8.37 ms | +2.67 |
| 100%（2x） | 7.57 ms | 7.48 ms | +0.09 |
| 空画布（2x） | 7.04 ms | 6.24 ms | +0.80 |

结论：**没有出现"两倍绘制成本"**——每栏只画视口内那块，增量来自多一次图像采样；
即使 2x DPR 也仍在 60fps 预算（16.7ms）内。当前基线里约 4.5–5ms 是既有的棋盘格
`fillRect` 循环，与本次特性无关；如果以后需要更多余量，可把它改成 32×32 平铺 brush。

## 12. 边界 / 未做

- **不做独立缩放**：两栏永远共享 Camera；以后也不打算做（B4）；
- **不做可拖分隔条**：固定 50/50 是为了让两栏视口同宽、同一世界坐标在左右栏的
  局部坐标完全一致；可拖会让两栏可见范围不同，拖框/锚点语义变复杂（C1）；
- 奇数宽度时右栏多 1px，适配尺寸取左栏；视觉上无感；
- 分屏不检查最小栏宽（C7：窄窗口仍强制并排）；极端小窗口下角标可能与内容重叠，
  但可正常缩放/平移；
- 无 bg 时不弹状态提示（Q6）；两个角标仍写「原图 / 成品图」，左栏实际是 merged——
  0 图层文件即此形态，属已知且可接受的降级；
- README 截图/动图由需求方自行更新（G3）；本文档不放新截图；
- 原型 `.scratch/split_spike.py` 仅用于验证视觉/交互/帧耗时，不随产品发布。
