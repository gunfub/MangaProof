# MangaProof 1.2.0 监制数据同步需求规格

> 目标版本：**1.2.0**（开发期 `1.2.0.alpha`）
> 对应设计文档：[1.2.0监制数据同步_技术设计.md](1.2.0监制数据同步_技术设计.md)
> 本文只写「要什么、不要什么、怎么算做完了」；怎么实现写在设计文档里。

---

## 0. 目标

MangaProof 的监制结果（通过 / 未通过 / 每个失败图层的红框与批注）目前只存在于本地
`.mangaproof.json`，团队协作时只能靠导出的 PDF 返修单人工转抄。

1.2.0 增加**监制数据同步**：把本地监制问题转换成平台（第一个平台为 **Poprako**）的
监稿问题，通过其 HTTP API 一次性写入目标章节。

```text
本地打开任务（PSD / 文件夹）
    ↓
完成监制，产生问题（类型 + 图层 + 红框 + 批注）
    ↓
顶栏「监制数据同步 → 同步到 Poprako…」
    ↓
登录（QQ 号 + 密码 → Bearer 令牌）
    ↓
选择 团队 → 项目集 → 作品 → 章节
    ↓
本地 PSD ↔ 章节复合图页 建立映射
    ↓
元数据转换（像素红框 → 归一化矩形；类型/图层/批注 → variant/layer_name/note）
    ↓
预览 + 二次确认
    ↓
POST 导入（整体替换该章问题）
    ↓
回读校验，结果写回任务文件
```

1.2.0 之后，第二个及以后的平台按**同一套模块边界**各自接入（见 §4），不在本版本实现。

## 1. 第一版明确不做

1. **不做**章节、复合图页、图片的上传（`page-artworks/alloc` + 预签名 PUT 那一套）。
   本版本只写「监制问题」。
2. **不做**自动同步 / 后台轮询 / 定时上传。每次都由用户显式操作。
3. **不做**双向同步：Poprako 的上传**在设计上就是单向上传**，永不把平台上的问题
   拉回本地（这是长期设计约束，不是"第一版暂缓"）。上传前后读取远端问题只有
   「统计将被清空的规模」与「保留未映射页现有问题」两个用途，见 §9.2。
4. **不做**流程阶段推进（`stage/advance`）。上传只替换问题，不改变条目的审核阶段。
   平台侧文档也明确「导入不推进 Review」。
   **2026-10-20 决策：上传后暂不标记完成**，将来是否推进需另行立项。
5. **不做**合并除「保留未映射页现有问题」以外的语义：已映射页一律以本地为准。
6. **不做**跨平台的公共抽象（基类 / 协议 / 注册表 / 共用对话框）。见 §4。
7. **不做**设置页入口，本功能只在顶栏入口进入。
8. **不做**可重绑快捷键。
9. **不做**依懒新增。`httpx` 与 `keyring` 已是主依赖，本功能不得引入任何新包
   （遵循 `AI-rules/依赖安全与环境管理规则.md`）。
10. **不做**离线缓存 / 断点续传：一次导入是一次完整替换，失败重试即重发。

## 2. 名词

| 名词 | 含义 |
|---|---|
| 监制数据 | 本地任务文件里的问题集合：类型（variant）、所属图层名、红框、批注、任务内编号 |
| 问题 Issue | Poprako 的一行监稿问题：`variant` + `layer_name?` + `rect?` + `note` |
| 复合图页 | Poprako 侧一个章节里的一张成品 PSD 合成图，有稳定 ID 与 `raw_ident`（原始 PSD 文件名或相对路径） |
| 映射 | 本地任务里的一个 PSD 文件 ↔ 一个复合图页 ID |
| 整体替换 | 导入接口的语义：请求里没出现的复合图页，其旧问题全部清空 |
| 归一化矩形 | 相对整张复合图的 `[0,1]` 坐标，左上原点，宽高为正 |

## 3. 入口

顶栏（`QMenuBar`）顺序固定为：

```text
文件   监制数据同步   设置   关于
              └── 同步到 Poprako…
```

1. 位置：**「文件」右边、「设置」左边**（新增第 2 项）。
2. 菜单名：`监制数据同步`。**不带助记符、不绑快捷键**（2026-10-20 需求方：同步不是
   高频场景；且此前的 `&T` 与既有快捷键冲突）。与「关于」一样只有标题。
3. 子项：`同步到 Poprako…`。第一版只有一个子项；接入第二个平台时**加一条同级子项**，
   不改变入口本身。
4. **入口永远可以点**（2026-10-20 决策）：即使没有打开任务也能进入，
   这样才能先登录、先设代理。进入后只把「目标章节 / 页面映射 / 预览与上传」
   三页置灰（侧栏项 + 页面本体），账号与代理照常可用；状态行提示
   「未打开任务：可先登录、设置代理」。
5. 桌面端与 Android 端**都必须可见可用**：Android 靠既有的
   `AA_DontUseNativeMenuBar` 让菜单栏回到窗口内，本功能不额外适配。
6. 不分配快捷键，也**不设助记符**；子项上不显示快捷键提示。
   （回归：`tests/test_poprako_dialog.py` 的"菜单能打开对话框"用例。）

## 4. 平台模块化（硬约束）

**一个平台 = 一个独立垂直切片**。后续平台的数据结构、章节层级、坐标语义、鉴权方式、
错误码、预览形式都可能不同，因此：

### 4.1 必须独立的部分

对每个平台，以下内容**各自一套，不得共用**：

| 层 | 内容 |
|---|---|
| 数据模型 | 该平台的团队/项目集/作品/章节/页面/问题结构（不套用别的平台的字段名） |
| 网络 | 鉴权方式、请求封装、分页、超时、重试、错误码映射 |
| 凭据 | 令牌存储位置（keyring 用户名各自一个）、明文回退策略 |
| 转换 | 本地 `Issue` → 该平台标注（坐标语义、字段裁剪、校验规则） |
| 界面 | 对话框的页面划分、控件组合、表格、预览格式、状态机、worker |
| 配置 | `settings.json` 里自己的顶层键 |
| 任务数据 | 任务文件 `integrations` 下自己的子键 |
| 测试 | 该平台自己的测试文件 |

### 4.2 允许共用的只有三处

1. 主窗口菜单里的**接线**（每个平台一条独立 action + 一个打开方法）；
2. 现有的通用**文本脱敏**工具 `mangaproof/update/redact.py`（纯字符串工具）；
3. 现有的**通用控件与主题**：`ui/widgets.py`（`NoWheelComboBox`、`ToggleSwitch`）、
   `ui/theme.py` 的色值常量。

### 4.3 禁止事项

- **禁止**新建跨平台的公共父类 / 抽象接口 / 注册表 / 动态发现机制；
- **禁止**把两个平台的界面合并成一套「可配置」的对话框；
- **禁止**为了让两个平台看起来一样，去抽公共版式模块 —— **版式代码按平台各写一份**，
  即使初版看起来相同。理由：后续可能按平台调整 UI（字段、页数、交互），
  共用模块会把「改一个平台」变成「改所有平台」。

### 4.4 新增一个平台要做的全部事情

1. 新建 `mangaproof/<platform>/`：`models.py`、`client.py`、`credentials.py`、
   `mapping.py`、`convert.py`、`errors.py`；
2. 新建 `mangaproof/ui/<platform>_dialog.py`（**自带**版式骨架）与
   `mangaproof/ui/<platform>_worker.py`；
3. `settings.json` 增加顶层键 `<platform>`；任务文件 `integrations` 增加子键；
4. 主窗口菜单加一条 action + 一个打开方法；
5. 新增 `tests/test_<platform>_*.py`。

不存在「改公共基类」这一步。

## 5. 登录与鉴权（Poprako）

1. 登录凭据：**QQ 号（qid）+ 密码**，明文只用于一次登录请求，**绝不落盘、绝不进日志**。
2. 令牌：登录成功后保存 `token` 与 `user_id`；后续请求统一
   `Authorization: Bearer <token>`。不使用 Cookie。
3. 令牌存储：
   - 桌面端优先系统凭据库：`keyring`，service `MangaProof`，username `poprako_token`；
   - keyring 实测不可用（或 Android 不打包 keyring）时回退 `settings.json` **明文**，
     且**必须在界面上明示**当前明文存储；
   - 探测方式与既有 CDK 一致：写入 → 读回 → 删除的实测可用性判断。
4. 「保持登录」（默认开）：开启时令牌跨次启动复用；关闭时退出程序即清除令牌。
5. 打开页面时若已有令牌，先调 `GET /users/me` 校验：
   - 成功 → 显示 `已登录 · 昵称 (qid …)`；
   - `401` → 清除令牌，回到未登录态并提示「登录已失效，请重新登录」。
6. 退出登录：清除本地令牌即可（服务端登出接口只清 Cookie，对 Bearer 客户端无意义，
   可发一次 best-effort 请求，失败不影响结果）。
7. 服务器地址可配置，默认 `https://api.poprako.com/api/v1`；非 http(s) 或空值时
   拒绝发起请求并提示，不静默回退。
8. 登录失败、网络失败、服务端 5xx 的错误提示必须说清「哪个环节失败」，不得只显示
   「失败」。

### 5.1 代理（2026-10-20 追加）

平台级网络设置，**独立成页**（不顺带塞在账号页）：

1. 语义与自更新功能一致：**留空 = 直连**；填写 = 只走该代理（不读系统代理环境变量）；
2. 支持 `http://` / `https://` / `socks5://`，可带 `user:pass@`；地址必须带协议；
3. 「测试连接」**只用输入框里的地址**访问 **`https://poprako.com/`**（2026-10-20 改：
   不再打谷歌——能不能上谷歌与能不能同步无关），并**显示往返延迟**；
   留空时测**直连**；**不保存**任何设置；
   拿到任意 HTTP 响应即算连通（401/403/404 也算），网络异常才算失败；
4. 「保存」才真的写入 `settings.json`，**立即重建客户端**并自动做一次同样的自检
   （状态行给出"已保存并生效 · 延迟"）；非法地址当场提示、不保存；
5. 代理里含账号密码时，保存前必须提示"会以明文保存在 settings.json"；日志里一律遮罩为
   `http://***@host:port`；
6. 已登录时保存代理不得掉登录态（保留令牌，重建客户端）；
7. **保存即生效必须可核对**：「当前生效」显示的是**客户端实际在用的代理**（不是设置里的
   字符串）；两者不一致时橙色标出"保存的代理未生效"。换下来的旧客户端要等正在用它的
   后台线程收尾后再关闭，不得把运行中的请求打断；
8. 「代理」是**每次请求都生效**的平台级设置：`PoprakoClient` 构造时就把代理交给 httpx
   （`trust_env=False`，留空即直连），不存在"只对探测生效"的情况。

## 6. 目标章节

### 6.1 逐级懒加载（2026-10-20 决策，替代"自动选第一项一路加载到底"）

1. 层级：**团队 → 项目集（workset）→ 作品（comic）→ 章节（chapter）**。
2. **每一级都必须等用户选**：下拉第 0 项固定是占位项（「请选择团队」等），
   **不许自动选中任何真实值**，也不许因为"选中了第一项"就自动去拉下一级。
3. 请求时机：
   - 第一次进入「目标章节」页 → 只加载**团队**；
   - 选团队 → 加载项目集（等用户选）；
   - 选项目集 → 加载作品（等用户选）；
   - 选作品 → 加载章节（等用户选）；
   - 选章节 → **不发请求**；
   - 点「**加载章节信息**」→ 才请求章节详情 + 复合图页 + 现有问题。
4. 团队列表来自「当前用户的成员关系」（含团队名与角色），不是全站团队列表。
5. 作品列表只列**未归档**的作品。
6. 任一上级改变：清空下级选择、丢弃已加载的章节信息，并把「加载章节信息」置灰。
7. 页面底部两个按钮：「**清空所有选择**」（团队列表保留，方便重选）与
   「**加载章节信息**」（仅当已选章节时可用）。
8. 选中章节并加载后显示只读信息：流程阶段、复合图页数、**现存问题数（将被整体替换）**、
   我在该团队的角色。
9. 以下任一情况**禁止上传**，并在页面上给出唯一一条警示：
   - 章节已发布；
   - 我在该团队没有「监制（REVIEWER）」角色（管理员身份不足以导入）；
   - 章节没有复合图页。

### 6.2 上次选择（标注，不自动选中）

10. 上次用过的团队 / 项目集 / 作品在下拉里追加「（上次）」后缀，**只标注不选中**；
11. 存独立文件 `poprako_last.json`（与 `recent.json` 同级、同性质），**不写 settings.json**；
    读写失败只记日志，绝不影响同步流程。

### 6.3 作品按名称匹配度排序（2026-10-20 决策）

12. 「目标章节」页四个下拉下面有一个胶囊开关「**按名称匹配度排序作品**」，**默认开启**，
    状态存 `settings.json → poprako.rank_comics`；
13. 开启时：选完项目集后，读取作品 → 与任务名匹配打分 → **全部重排**（不设阈值）；
    排序期间弹**模态进度窗**（加载 / 匹配 / 排序三阶段，不可取消，**只要开启就一定弹**）；
14. 关闭时：按平台返回顺序显示，不弹进度窗、不做高亮；
15. 匹配到的字符在**下拉行内**标绿（`#4caf50`）；
15.1 **匹配率直接写进下拉框**（2026-10-21 需求方，替代原来"作品下面单独一行"）：
   每行形如 `94% 某漫画 第二部` —— 最前面预留固定宽度只放匹配率，
   **百分数右对齐、作品名紧接着左对齐**；百分数四舍五入到个位（`0.9447 → 94%`），
   颜色沿用匹配高亮绿；**收起后的下拉框里同样显示**；
   未开启排序（没有分数）时不显示百分数、也不预留那一段。
16. 任务名取"返修单默认名"的同一套规则（`output` 目录还原成上一级，见 §6.4）。

### 6.4 任务名（匹配用的"当前作品名"）

19. 与返修单默认名**同一套规则**（唯一实现 `utils/task_naming.py`）：
    目录名是 `output`（不区分大小写）时取上一级目录名；否则文件夹任务取目录名、
    单 PSD 任务取文件名（去扩展名）。两处不得各写一份，避免漂移。

### 6.5 健壮性

17. **空列表必须说明**（2026-10-20）：任一级返回空时，状态行给出「该团队下没有项目集」
    这类明确提示，并清空下级选择；不得静默留白。
18. **结构不符必须报错**（2026-10-20）：接口返回的 `data` 形态与约定不符时（例如
    列表被包成对象却没取到对应字段），抛错并在状态行显示——不得当成"空列表"处理。
8. **空列表必须说明**（2026-10-20）：团队 / 项目集 / 作品 / 章节任一级返回空时，
   状态行给出「该团队下没有项目集」这类明确提示，并清空下级选择；不得静默留白。
9. **结构不符必须报错**（2026-10-20）：接口返回的 `data` 形态与约定不符时（例如
   列表被包成对象却没取到对应字段），抛错并在状态行显示——不得当成"空列表"处理。

### 6.6 角色与章节分工（2026-10-21）

19. **两种角色必须分开显示**：团队里的「账号角色」（`GET /members/me`）与这一章的
    「项目角色」（`GET /assignments?chapter_id=…`）。上传权限只看**项目角色**的
    `REVIEWER`（监修）位——团队角色再高，没分到这一章也导不进去。
20. 术语随平台：本窗口内 `REVIEWER` 一律叫**监修**（与 poprako-web 一致），
    流程阶段名里的同一位也写作「监修」；软件其它地方仍叫「监制」，互不影响。
21. 「加载章节信息」顺带读取该章节的全部分工；「项目角色」在加载前显示 `—`，
    加载后没参与显示「无（未参与）」，有参与显示角色名 + 「（可导入）/（不可导入）」。
22. **「加入监修分工」按钮**：点了才发 `POST /assignments/join {chapter_id, roles: 32}`。
    置灰条件（置灰 + tooltip 说原因，不隐藏）：
    - 没登录 / 没读章节信息（或分工没读到）；
    - 账号角色里没有**监修或管理员**（2026-10-21 确认：管理员也允许自助加入）；
    - 项目角色里已经是监修；
    - 正在请求中。
23. 加入成功后立刻刷新「项目角色」与上传门禁；失败按异常类型给话
    （403 → 该章节不接受自助加入，请联系管理员）。
24. 分工读不到（网络/权限）时，上传门禁退回账号角色做提示性预检，最终以服务端为准。

## 7. 页面映射

1. 映射对象：本地任务的每个 PSD 文件 ↔ 章节的一个复合图页 ID。
2. 自动匹配按以下优先级逐条尝试，命中即锁定；**有歧义一律不猜**：

   | 顺位 | 规则 |
   |---|---|
   | 1 | 本地相对路径 == `raw_ident`（统一 `\`→`/`、大小写不敏感） |
   | 2 | 文件名（basename）== `raw_ident` 的 basename |
   | 3 | 去扩展名的 stem 相等 |
   | 4 | 数字段相等（`001.psd` ↔ `001`、`page_01` ↔ `01`） |

3. 另提供「按顺序对齐」：数量相等时按自然序一一对应；数量不等时只对齐能确定的前 n 项，
   其余保持未映射。
4. 手动改映射：每行一个下拉框，可选任一远端页或「不同步」；选中已被别的行占用的页时，
   自动解除原行映射，并在状态行提示，不弹框。
5. 三种未映射情形必须分别呈现：
   - 本地页有未映射且**含问题** → **阻塞上传**（橙色，列出文件名与问题数）；
   - 本地页有未映射但无问题 → 提示但不阻塞；
   - 远端页有未映射 → 信息性提示（列出前若干页与它们的旧问题数）。
6. 映射随任务保存（`integrations.poprako.pages`），下次打开同一任务自动恢复。
7. 切换章节时若存在手工映射，必须二次确认「切换会清空当前映射」。

## 8. 元数据转换

### 8.1 字段映射

| 本地 `Issue` | Poprako `IssueInstr` | 规则 |
|---|---|---|
| `type` | `variant` | 去首尾空白；空白则用 `问题` 兜底（服务端拒绝空白） |
| `layer_name` | `layer_name` | 去空白；为空则**整键省略**（= 整张复合图） |
| `comment` | `note` | 原样保留，含换行与空串 |
| `rect`（像素） | `rect{x_coord,y_coord,width,height}` | 见 §8.2；退化则**整键省略** |
| 任务内编号 `issue_no` | 数组顺序 → 服务端 `index` | 升序发送，保证两端编号一致 |

**只允许出现这四个键**：服务端 `additionalProperties: false`，多一个字段整个请求 422。

### 8.2 红框归一化

以该 PSD 的**画布像素尺寸** `W × H` 为基准：

```text
x = clamp(x_px / W, 0, 1)        y = clamp(y_px / H, 0, 1)
w = min(w_px / W, 1 - x)         h = min(h_px / H, 1 - y)
若 w ≤ 1e-6 或 h ≤ 1e-6 → 省略 rect
结果保留 6 位小数
```

- 画布尺寸从 PSD 文件头读取（26 字节），**不解析整份 PSD**；
- 读不到尺寸且该页有问题带红框 → 阻塞上传并指出文件。

### 8.3 体积

payload 预估超过 **2 MB** 时在界面上警告（服务端 HTTP body 上限未公开），
不静默截断、不拆分成多次导入。

## 9. 上传

### 9.1 语义与安全阀

1. 语义：**整体替换**目标章节的全部当前问题；被替换的问题会拿到全新 ID。
2. 三个安全阀：
   1. 已映射页：本地为唯一真相，**显式发送**（0 条也发）；
   2. 未映射的远端页：默认**保留**其现有问题（先读回、原样写回），用户可切到「清空」；
   3. 本地有问题的页没有远端对手：**阻塞**，必须先解决映射。
3. 上传前必须二次确认，确认框固定写出四要素：目标章节、写入页数/条数、清空页数
   （列前 5 个）、保留页数；用户必须勾选「我确认整体替换该章问题」才能继续。
4. 上传后回读 `GET /chapters/{id}/issues` 校验条数与页数，结果（时间、页数、条数）
   写回任务文件。
5. 失败处理：
   - `401` → 清令牌，提示重新登录（保留当前映射与选择）；
   - `403` → 提示需要该章节的「监修」分工，并提示可先点「加入监修分工」；
   - `422` → 提示提交内容被拒绝，并附本地预检结论；
   - 网络错误/超时 → 提示可安全重试（整体替换幂等），不自动反复重试；
   - 其余按 HTTP 状态给出中文说明。
6. 上传中途不修改任务数据；只有成功且校验通过后才写 `last_upload_*`。
6.1 **导入成功、回读失败要分清楚**（2026-10-21）：导入请求一旦返回成功，数据就已经
   写进平台；此后的回读校验失败提示为「已导入，但回读校验失败：…」，
   不得笼统说「上传失败」。
6.2 **进度条要走到 100%**（2026-10-21）：上传分「导入 / 回读校验」两段，进度条按
   0/2 → 1/2 → 完成 显示 0% / 50% / 100%；成功后停在 100%，只有负载变化
   （换章节、改映射、改保留开关）才回到 0%。

### 9.2 单向上传的边界（长期约束）

Poprako 的上传是**单向上传**：MangaProof 只写、不读回业务状态。

允许读取远端问题（`GET /chapters/{id}/issues`）的**唯一两个用途**：

1. 统计「本次将被清空多少条」并在确认框里展示；
2. 当「保留未映射页现有问题」开启时，把这些页的问题**原样写回同一次导入请求**。

禁止：

- 把远端问题写入任务文件、参与本地统计、显示为本地问题；
- 提供任何「从平台拉取 / 覆盖本地」的入口或按钮；
- 依据远端问题反向修正本地的通过/未通过状态。

上传后的回读校验只比较**计数**并记录时间戳，不保存远端问题内容。

## 10. 界面规范

遵循 [`设置页设计规范.md`](设置页设计规范.md) 的**完整形态**（侧边栏 + 页头 + 分割线）：

1. 窗口标题 `MangaProof 监制数据同步`；默认 **1024 × 640**，最小 **864 × 540**
   （2026-10-21 需求方：高度加大，默认比例与主界面一致——主窗口 1440×900 = 1.6，
   这里 1024×640 也是 1.6；同日晚些再加「项目角色」一行后由 960×600 抬到这一档）；模态。
2. 四边留白 24（**下边 16**），侧边栏宽 180，主体间距 24；行距 16；文本与控件间距 10；
   控件右缘统一压在 `窗口宽 − 24`。
2.1 行高只由内容决定（输入/下拉 30、开关 20、只读 18），**不许被布局拉伸**；
   行与行之间恒为 16 —— 与设置页同一套（2026-10-21 需求方："各项之间竖向间隔不统一"）。
2.2 字段列**每页各自一条**（与设置页完全相同）：本页填充型行统一取最长标签的宽度，
   同页内输入框/下拉框左缘严格一致；翻页时各页的列可以不同。
3. 侧边栏五项（顺序即流程）：**账号 / 代理 / 目标章节 / 页面映射 / 预览与上传**；
   五页在构造时一次建好并常驻（只切显示，不重建）。
3.1 侧栏在**同一个外框**内分两组：账号 / 代理一组，目标章节 / 页面映射 / 预览与上传
   为另一组，后者用「深一档底色 + 1px 细边 + 圆角」的内嵌框包住（2026-10-20 决策：
   用容器表达"这三页是前后工序"；**不加序号、不加箭头**，两组条目文字左缘严格对齐）。
3.2 侧栏导航**永不滚动**（2026-10-20 需求方）：5 项一屏放得下，列表高度按条目实测行高
   + 列表自身 frame 内缩定死，`verticalScrollBar().maximum()` 必须为 0；滚轮停在侧栏上
   **什么都不会发生**（既不推侧栏，也不带动右侧内容区）。仅设
   `ScrollBarAlwaysOff` 不算修好——那只是把条藏起来，滚轮照样能推动列表。
4. 页头 = 15px 粗体标题 + 一行灰色说明 + 1px 分割线（上下各 16），滚动时不动。
5. 行 = 左文本 + 右控件：下拉框/输入框为填充型（本页字段列对齐、占满到基线），
   开关/按钮为右对齐型。行文本与控件 tooltip 联动。
6. 开关一律用胶囊 `ToggleSwitch`；下拉框一律用 `NoWheelComboBox`（滚轮不改值）。
7. 控件禁用时**该行文本一并置灰**，且**不隐藏**（不做 show/hide，避免布局跳动）；
   禁用原因写进 tooltip。
8. 底部条：左为**上下文/状态行**（未登录 / 已登录 昵称 · 章节 · n/m 已映射 · k 条问题；
   异常时变橙/红），右为**关闭**。Esc 与窗口 X 等价于关闭。
8.1 底部条固定高 38（容得下「映射页」的两行摘要），整条落在「侧栏下边缘 → 窗口下边缘」
   这块空间的**正中**（上 16 / 下 16）；状态文字垂直居中（2026-10-21 需求方）。
8.2 「页面映射」页的两行摘要**不放在页面里**，而是并进底部条、与状态文字同一行，
   底边对齐；只有映射页显示（2026-10-21 需求方：表格要一直伸到侧栏下边缘）。
9. 上传按钮位于「预览与上传」页的**固定动作行**（不随内容滚动），主按钮在最右；
   上传中按钮禁用、文案变「上传中…」，进度条常驻占位。
9.1 四页的动作行（退出登录/登录、测试连接/保存、清空所有选择/加载章节信息、
   复制/导出 JSON/上传）都固定在滚动区**下方**，**底边与侧栏下边缘齐平**；
   同一行内按钮间隙统一为 **6px**（= 设置页「确定 / 取消」的间隙，2026-10-21 需求方）。
9.2 两个进度条（排序进度窗 / 上传页）与主程序「载入 PSD」的 `QProgressDialog`
   同款：主题默认高度、显示百分数，不再压成细条。
9.3 代理页（新增）＝ 代理地址输入框（填充型）+ 只读「当前生效」行 + 一句说明 +
   右对齐的「测试连接」「保存」；测试不落盘，保存才生效。
10. 关闭窗口**不丢**已完成的结果：登录态、选择、映射、上次同步记录都保留（映射写回任务）。
11. 全部按钮文案为中文，不依赖 Qt 翻译。
12. 版本明确不采用「确定 / 取消」语义：本窗口是同步工作区，不是设置表单；
    唯一的破坏性动作「上传」由二次确认把关。

## 11. 设置与任务数据

### 11.1 `settings.json`（新增顶层键 `poprako`）

| 键 | 类型 | 说明 |
|---|---|---|
| `base_url` | string | API 基址，默认 `https://api.poprako.com/api/v1` |

| `preserve_unmapped` | bool | 未映射的远端页保留现有问题，默认 `true` |
| `rank_comics` | bool | 作品是否按名称匹配度排序，默认 `true`（2026-10-20） |

### 11.2 任务文件 `.mangaproof.json`（新增 `integrations` 对象）

```jsonc
"integrations": {
  "poprako": {
    "team_id": "", "workset_id": "", "comic_id": "",
    "chapter_id": "", "chapter_label": "",
    "pages": { "001.psd": "pa_7f3c" },
    "last_upload_at": "", "last_page_count": 0, "last_issue_count": 0
  }
}
```

- `schema_version` 保持 1（纯加性字段）；
- 旧版本读到新文件忽略未知键；新版本读到旧文件按空对象处理；
- 平台只能读写自己那个子键。

## 12. 安全与隐私

1. **不上传** PSD 本体、合并图、任何本地文件；只上传标注数据（文本 + 归一化矩形）。
2. **不上传**本地绝对路径：发给平台的只有文件名/相对路径（用于映射）与标注。
3. 密码：只在内存中存活到登录请求返回，不写文件、不进日志、不进错误信息。
4. 令牌：不写日志、不进异常文本、不出现在 URL 里；所有记录前先过脱敏。
5. 明文回退存放令牌时，界面必须明确告知（不让用户误以为已在系统凭据库）。
6. 不新增依赖；不修改系统 Python 环境；代理等网络设置不写入系统配置。

## 15. 验收标准

- [ ] 顶栏顺序为 `文件 / 监制数据同步 / 设置 / 关于`；入口**永不置灰**，无任务时也能打开
      （账号 / 代理可用，流程三页置灰）；Android 同样可见。

- [ ] 团队 → 项目集 → 作品 → 章节 四级可选，信息行显示阶段/页面数/现存问题数/角色。

- [ ] 自动匹配 + 顺序对齐 + 手动改映射均可用；占比冲突自动解除；映射随任务保存。

- [ ] 断网、401、403、422、5xx 均有中文提示，且提示中不含令牌。
- [ ] 对话框版式符合 `docs/设置页设计规范.md`（基线 / 行距 / 字段列 / 置灰 / 禁滚轮）。
- [ ] 全程无新增依赖；`uv run pytest` 全绿。
